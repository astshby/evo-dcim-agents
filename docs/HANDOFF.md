# 给项目开发者与后续 Agent 的交接

## 从这里开始

先读本文件、`UPDATE_POLICY.md`、`IMPLEMENTATION_STATUS.md`，再运行测试和离线demo。用户将直接把此Git仓库交给其他Agent继续开发；不要假设能读取此前聊天或本地旧路径。

## 1. 用户的研究目的

用户已研究DCIM电路与生成器，目标是Agent辅助完整DCIM Macro的结构组织、模块放置与布局布线，提高整体PPA，并特别重视跨设计/跨PDK经验迁移。不是“让LLM画几个单元”就完成，也不是只调数字flow参数。Memory Cell、驱动、乘法、Adder Tree、累加/后处理等需要协同。

现实执行基础预期是已有PDK/Cadence Innovus与Virtuoso、Codex操作脚本能力。当前开发环境没有实际PDK/EDA，因此只留下接口，不能假装已跑真实流程。用户希望复用Codex，而不是重造完整coding-agent harness。

## 2. 讨论逐步确定的关键选择

1. 论文与开源实现是借鉴，不照搬；实现基于固定提交的实际代码行为，论文差异单独说明。
2. 用Evo式控制器管理迭代，但DCIM可以从有效检查点继续，不强制每轮重新生成全设计。
3. 操作是有边界的工程设计变换，不等于每个token/文件读取；专业算法负责几何/数值求解。
4. 候选来源可为历史经验、专业布局函数、Codex。三者不是互斥类别，同操作可同时来自多个来源。
5. GEPA接受“方式A”：多套策略提供互补候选，不把多个模型赞同当作物理验证。
6. ACE作知识手册格式；SkillOpt修订可执行规程；MEM/JIT分别选择经验与工程动作，Q不混用。
7. ChipMEM有价值的部分是验证来源和工具恢复，不是其原检索方式必须完整保留。
8. 用户后来明确简化：一个work一套PDK+环境+目标配置；session记忆属于work，不增加跨session复杂配置维护。
9. **Skill与ACE只在session完成后修改。**内部事实、工具统计、动作样本和记忆效用可以更新。
10. **Episode压缩成状态机卡片**，不整段历史重复输入；原始日志保留作按需证据。
11. Session摘要采用“策略—行动选择—实现效果”，附起点、模式和证据引用，不用摘要覆盖原始事实。
12. 后续允许简化/删除冗余方法；不要为了凑齐七篇论文强行叠七个完整循环。

## 3. 定义不要再换回论文命名

work = 固定任务合同；session = 一轮包含多个episode的迭代窗口；episode = 有边界的设计试验；step = 可观察具体操作。EvoTest原论文的episode可能对应我们更外层的窗口，这种映射是刻意的。

Session可继续/分支/重开；跨PDK建立关联新work，迁移意图和经验，不迁移旧通过结论。当前实现仅支持继续/指定已有检查点，不支持完整工艺迁移。

## 4. 当前交付到底是什么

是可运行、可测试的**初始化整合**：一套主循环、持久化与更新边界、两个数值机制子集、种子知识/Skill、Codex工作区和显式CLI启动边界。不是七仓库完整联调。

没有自动调用LLM的Reflector/Curator，没有专业布局函数推荐器，没有FAISS/embedding，没有真实Cadence命令与独立评价器，没有Codex App Server桥接，没有真实PPA/跨PDK效果验证。

Mock的候选和改善是fixture。`publish-mock`的gate也是测试输入，不能当可信验证。Code review需特别检查任何新路径是否会把这些内容混入真实数据。

## 5. 下一位开发者的推荐验收顺序

### A. 先审计初始化实现

检查Python接口、异常与幂等性；增加坏输入/崩溃恢复测试。数据库和导出视图是单控制器设计，暂不引入并发worker。确认code/docs一致，不要把初版说明当实现证明。

### B. 打通一个可控的Codex任务，不接EDA

先检查本地安装版本的 `codex exec --help`；验证准备目录、Skill实际加载、JSON事件和schema输出。一次明确授权的调用即可，不运行长循环。记录实际调用/失败，不能把fake executable测试写成真实模型联调。

### C. 提议者与执行者边界

将现有人工候选接口连接到两个只提议不执行的Codex上下文。统一动作合同、去重、合法性检查。记录未执行候选的效果为未知。再连接受限执行角色，禁止其自改评价器。

### D. 只接一个可信EDA算子

由用户提供环境后，先实现 capabilities、submit/poll/cancel、输入制品哈希、独立evaluate。把许可证/脚本/设计错误区分。不能使用模型报告直接settle。完成真实评价协议后才开放mode=real。

### E. 再接慢更新与迁移

ACE/Skill候选生成 -> session末暂存 -> 独立回归评价 -> 下session发布。按REFERENCES的固定代码逐项适配，必要修改列差异。跨PDK先做经验适用性过滤与目标域复核，不直接复制Q。

## 6. 用户尚需继续评估的规约

- 真实动作粒度和可变参数目录；哪些结构/接口固定。
- 真实检查阶段、PPA归一化、容差、失败/修复奖励与执行成本。
- 历史状态相似性：几何/拓扑特征，不应停留在当前state_key占位。
- 未知动作探索预算，多记忆信用分配，文本变化后的旧统计复核。
- Session结束条件，连续停滞阈值，哪些部分可从旧设计继续。
- 真实发布门的可信边界及必要回归集。
- PDK内容外发政策、远程权限、共享机器上的认证/许可证与作业隔离。

这些是待定设计，不要擅自给出“工业最优默认值”。

## 7. Agent指令分离

- 根 `AGENTS.md`：公开开发指令，便于任何接手Agent理解项目。
- `templates/AGENTS.runtime.md`：实际产品运行worker指令，准备时复制为运行目录AGENTS.md。
- `templates/AGENTS.override.local.example.md`：可选本地开发补充，复制为Git忽略的AGENTS.override.md。覆盖文件必须显式要求读取根AGENTS.md。
- `.agents/skills/maintain-framework`：开发专用技能，不进入运行目录。
- `skills/*`：运行种子技能；work内采用固定副本，session中不可变。

Codex识别复数AGENTS.md，不把用户口语中的单数AGENT.md创建成一个默认不会加载的文件。

## 8. 交接质量要求

每次提交写明：改了什么、涉及哪些规约/源码、实际跑了哪些测试、没有跑什么、下个可验收目标。不得把装好依赖=联调成功、联调成功=算法有效、源PDK成功=跨PDK有效。

保留小而清晰的接口。先验证一条链，再引入依赖。不要复制私有论文、PDK、完整第三方仓库或认证文件。公开仓库权限不意味着可重新授权第三方代码；本项目也尚未替仓库所有者选定发布许可证。
