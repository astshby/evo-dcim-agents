## 已知技术限制

1. SQLite存储单个JSON状态是初始化取舍，数据量增加后再拆表；目前单控制器，文件投影不保证多进程并发。
2. 事件来自控制器和当前runner；不是Codex全部内部行为的强制拦截。
3. Real模式可建work/准备上下文，但真实评价摄取与发布禁用。需要可信适配器，而不是增加一个接受任意JSON的入口。
4. Mock发布输入的gate用于协议测试，不是已认证的独立评价结论。真实promotion不能沿用同样信任假设。
5. 工作区隔离减少误操作，不等于阻止恶意本地用户/模型读写；全局Codex设置与工具能力需单独审查。
6. Session报告是关闭时快照；延迟评价通过episode更新，不自动重写历史报告。
7. Episode卡片不等于完整几何状态；当前state_key必须人工合理设置，不能凭一个“拥塞”标签泛化所有设计。
8. 发布任何文本后保守重置数值估计，原始证据仍留在episode。未来可改成受影响条目的选择性复核。
9. 当前无私有数据脱敏、许可证检测或PDK capability抽取器；接口不会自动提供这些能力。
10. 当前不提供完整artifact lineage失效传播、失败执行的恢复调度、长期数据清理策略。
