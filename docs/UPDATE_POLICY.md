# V0 更新策略与评价合同

本文承接用户最后确认的边界：**一个 work 一套 PDK/环境/目标配置；所有 session 记忆属于 work；episode 用压缩状态机记录；ACE 和 Skill 仅在 session 完成后修改。**

## 1. 四类更新不得混淆

记录（保存发生过什么）、统计（更新次数/效用）、整理（归纳规则）、发布（让新文本生效）是四件事。短期记忆也要持久化；长期记忆不等于Skill。

| 时点 | 更新 | 禁止 |
|---|---|---|
| step调用前 | 记操作/输入/作业；预算与权限检查 | 预判为成功 |
| step完成后 | 实际返回、状态、耗时、工具成功/失败次数 | 改ACE/Skill；把环境故障当物理失败 |
| episode可评价后 | 设计去向、动作效果、注入记忆的共享小幅反馈、状态卡片 | 奖励未注入记忆；奖励未执行候选 |
| episode结果未定 | 保留PENDING与证据引用 | 用缺失结果当负分 |
| session完成 | 对比报告、三元组摘要、ACE/Skill候选补丁 | 为了“进化”强制改文档 |
| 验证通过后 | 发布下一session的文本版本 | 覆盖原始来源、将Mock变为真实证据 |

当前事实/工具统计/记忆数值可在session内变化，正文不能变。Session指令固定不意味着策略完全静态：选择器仍使用新数值和新事实。

## 2. 更新对象对应论文与当前实现

- **EvoTest**：借用Act/Evolve分离。此项目将慢更新窗口置于session末；不实现上游配置树UCB，也不把它说成标准bandit统计。
- **JitRL**：参考公开代码的 `normalized_prob + weighted_normalized_advantage`。保留正优势最大值归一化和episode权重；不默认切换成论文logit公式。简化为同state_key/动作键检索；未知动作按基线，不强行负分；另有项目自定义的有种子epsilon探索。没有FAISS、LLM Evaluator、跨步折扣信用分配或自动补入历史动作。
- **MemRL**：数值更新采用其gamma=0形式。实际提供的记忆获得共享反馈，新案例复用效用从0开始。不声称因果归因。当前精确state_key检索是临时方案，不是原Two-Phase Retrieval。
- **ChipMEM**：吸收调用后记录及验证来源思想。当前只有成功/失败计数和接口；分层贝叶斯模型、nudge、PASS封装能力尚未移植。
- **ACE**：状态卡片和增量条目。当前不会调用LLM Reflector/Curator；补丁由显式输入提供。本文需要的replace/delete是项目新增，不冒称上游默认已经实现。
- **SkillOpt**：受限append/replace/delete、旧版保存、候选hash和门控边界。没有自动反思、epoch slow/meta循环或真实holdout试验。
- **GEPA**：方式A的多提议Skill种子和候选source字段；目前候选是fixture/外部输入，未运行Pareto搜索、反思模型或并行Codex提议者。

## 3. 先评价，再分别结算

四个独立维度：执行状态、当前阶段设计检查、可比PPA、成本。只有输入检查点匹配、来源mode匹配、stage/corner匹配且所需数据齐全，才能比较。

当前Mock evaluator：
1. blocked/error -> 不可评价，动作和记忆reward=None；工具统计仍更新。
2. missing checks/metrics、阶段不一致、pending -> PENDING，不学习最终质量。
3. 明确设计检查失败或硬指标超界 -> reject，reward=-1。
4. 全部通过 -> 按固定主目标比较。容差内reward=0；改善adopt；退化keep_branch。正负reward使用基线归一化并裁到[-1,1]，是项目奖励约定，不是论文原奖励。

没有功耗激励、寄生提取或物理检查的合成值绝不升级成“真实PPA”。实际工具接入后需要扩展单位、corner、激励和依赖失效检查。当前尚未支持“违规基线逐渐修复”的分阶段目标；不能绕过硬检查来伪装改善。

## 4. 三个接受门

- **设计门**：episode后决定新的工作检查点。保持最佳有效设计；探索分支可以更差。
- **知识门**：session后确认来源、条件、反例和事实。单次案例不升级为无条件规律。
- **策略门**：新Skill必须在相同检查点/任务及预算下比较；不把后轮更好的起点当作提示词改进。

真实知识/策略发布门尚未连接独立评价器。`publish-mock` 仅验证边界协议，要求显式确认和绑定base/candidate哈希的合成gate。这个JSON不具备可信评价器签名，不能用于真实发布；mode=real/replay时拒绝结算/发布而非静默降级。

## 5. Session末问题路由

发现知识缺口 -> ACE候选；执行顺序/停止条件缺陷 -> Skill补丁；候选重复或遗漏 -> 提议者Skill；仅评分偏差 -> 更新统计；环境错误 -> 适配器/恢复流程。规则已经正确而执行未遵守，优先改检查和约束，不无限追加提示词。

默认最多3条文本编辑；数量不等于语义幅度，仍需审查diff。候选不修改固定work合同、工具代码、评价器和权限。一次优先修改一个组件，若ACE/Skill一起变化，需要评价组合后的行为。

## 6. 幂等、延迟反馈与恢复

同一episode相同评价重送不重复学习，冲突重送报错；工具完成事件同样去重。PENDING可在session关闭后补结算，但若当前设计已推进，不自动移动新的head，只保留分支。关闭session报告是当时快照，延迟结果见episode最新记录，不悄悄改历史结论。

数据库提交后才导出文件；视图损坏可重建。工具在执行中崩溃的远程job恢复仍是TODO，不允许靠重跑制造重复作业。

## 7. 文本发布后的数值兼容性

V0为保守起点：发布新文本时保留原始episode证据，但清空当前动作估值样本、将记忆效用复位。不是论文行为；避免新策略无条件继承旧Q。下一阶段可以仅衰减受影响统计，必须先增加适用性测试。不会给每个session复制环境配置或复杂版本树。

## 8. 停止与预算

代码限制每session episode数、每episode与session的外部step数。Codex CLI接口仅限制墙钟时间；其内部工具次数、账户额度、token预算不是当前硬保证。报告明确这个边界。发布候选生成与验证也应计入预算，后续不能作为“免费优化”忽略。
